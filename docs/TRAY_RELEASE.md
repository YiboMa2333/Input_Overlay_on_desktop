# Tray integration and portable build verification

The executable is a Windows x64 GUI application, with no console and no OBS,
Python or developer tools required at runtime. Its original keyboard/mouse icon
is generated by `tools/make_icon.py` and embedded at multiple sizes. No upstream
image or external font asset is used. The embedded manifest requests normal-user
execution and PerMonitorV2 DPI awareness.

Shell_NotifyIconW uses a stable per-user/configuration GUID and version-4
notifications. Double-click opens Settings; right-click requests the menu. The
menu provides Open Settings, Show/Hide Overlay, Edit Overlay, Lock Overlay,
Reset Position and Size, Start with Windows and Exit. Closing Settings leaves
input capture and the overlay running. Exit removes the icon and shuts down
capture. Explorer's TaskbarCreated broadcast and periodic retries restore icons.

A named local mutex prevents duplicate instances for the same user/session and
configuration directory. A second ordinary launch activates the existing Settings
window; a second `--tray` launch exits silently. Isolated test profiles deliberately
have separate identities. Startup remains optional and disabled by default.

## Tests actually performed on Windows, 16 November 2026

Local Release build: LLVM-MinGW 20261104 UCRT x64, CMake 4.5.0. Native tests cover
ShellExecute/open launch (the same Shell verb used by double-click), custom icon
presence, duplicate launch, Settings lifecycle, show/hide, edit drag/resize,
locked cross-process click-through, persistence, hotkey conflicts and graceful
exit. Actual pointer double-click on the notification icon opened Settings.
Physical File Explorer double-click was not separately performed.

With explicit user authorization, `tools/verify_explorer_restart.ps1` stopped the
verified Explorer shell process. Explorer PID changed from 11028 to 11764; the
overlay process 21036 survived and its GUID notification icon returned. Results:
`build/explorer-restart-verification/results.json`. The script requires an
explicit `-RestartExplorer` switch and restores the shell during cleanup.

The full-suite run could not reliably acquire the notification overflow popup
and reports NOT EXERCISED for right-click. A separate run against the packaged
executable successfully opened the actual right-click menu and invoked Lock,
then failed to reopen the popup for the subsequent Edit check. That packaged
integration run therefore failed; repeated overflow interaction remains an open
test reliability or interaction issue. Its log is `build/packaged-integration.log`.
Menu commands are also tested directly. Callback
handling accepts both right-button-up and context-menu notifications, suppressing
duplicates. A complete repeated physical menu sequence is not claimed as passed.

One display at 150% DPI was available. Physical monitor disconnection and mixed-DPI
movement remain untested, as do actual next-logon startup, MSVC compilation and
remote GitHub Actions execution. Position is changed through Edit mode or the
configuration file; Settings currently exposes reset rather than numeric screen
coordinates. Binaries are unsigned.

## Earlier private artifact and subsequent review

`tools/package.py review --build build/llvm --output dist/tray-review
--toolchain llvm-mingw-static` creates a marked private review ZIP, executable,
dependency/hash manifest and matching source ZIP. Supply `--cmake` when CMake is
not on PATH. Review ZIPs are for local evaluation and must not be published.
That was the pre-audit state. The subsequent LLVM-MinGW dependency/licence audit
and instructions for the reviewed release package are in RELEASE_REVIEW.md.
Only the newly reviewed package is covered; older private staging remains private.
The Windows workflow builds x64 Release with static MSVC runtime and uploads a
portable ZIP only after the explicit source/toolchain-bound approval gate passes.

Extract the complete approved package before launching; keep its notices and
corresponding source. No installer or service is necessary. If the HUD is hidden,
use Show Overlay; if misplaced, Reset Position and Size. Windows may place the
icon in notification overflow. For a startup failure after moving the executable,
disable and re-enable Start with Windows at its new permanent path.
